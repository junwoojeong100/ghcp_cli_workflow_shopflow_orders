# Change Request CR-2026-014 — VIP Refund Policy Improvement and Stronger Control of High-Value Refunds

| Item | Details |
|---|---|
| Requesting department / requester | Customer Experience (CX) team / Hyeonup Kim, Team Lead |
| Request date / desired go-live date | 2026-10-16 / 2026-11-02 |
| Priority | High (includes an audit finding) |

## 1. Background
- Over the last 3 months, VIP customers have complained more often that "the refund period is too short." (VIP churn must be prevented.)
- Because the refund reason is not recorded, **refund root-cause analysis is impossible**.
- We received an internal audit finding that **there is no internal approval procedure** for high-value refunds.

## 2. Requirements
| ID | Requirement |
|---|---|
| R1 | Extend the refund period for VIP customers to **60 days** from the purchase date. (Standard customers stay at the current 30 days.) |
| R2 | Make the **refund reason** a required input when a refund is requested. (For root-cause analysis and audit.) |
| R3 | A refund whose amount **exceeds ₩1,000,000** is not approved automatically; it is received in **pending admin approval** status. |
| R4 | Change the related wording on the customer screen, in the notification e-mail and in the refund policy document to match the policy above. |

## 3. Constraints
- Existing customer, order and refund data must be **kept without loss**, and the change must go live **without a service interruption**.
- If there is any impact on the mobile app (including legacy versions), **tell us in advance.**
- The basis of the change and the approval history must be **traceable** for audit response.

## 4. Business acceptance criteria (done when all of these are true)
1. For a VIP customer, an order bought 45 days ago can be accepted for a refund; for a standard customer, an order bought 45 days ago cannot.
2. If a refund is submitted without a reason, the user sees a message asking for the reason. (How to apply this is to be agreed with IT.)
3. A refund over ₩1,000,000 appears in the 'Pending approval' list of the admin console, and it is not refunded before approval.
4. The refund-period wording on the customer screen, in the e-mail and in the policy document matches the actual policy.
